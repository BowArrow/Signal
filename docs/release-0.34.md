# Signal 0.34

Run now supports a saved video-production schedule for each business. Each cycle queues one five-second cloud character shot, waits for full-clip approval, asks an agent to assemble an ad from that cycle's approved shot, and waits for finished-ad approval. YouTube publishing uses its existing separate policy. A production cycle is not a publication or a sale.

Cycles and planning tasks persist in SQLite. Repeated scheduler checks and app restarts retain their task IDs. Missing credentials, tools, cast or budget prevent a new cycle. Pending reviews hold the current cycle even after its interval has elapsed. Genuine planning failures remain visible; tasks interrupted specifically by operation Pause resume with the original ID when the business runs again. Paused or disabled production cannot submit cloud shots or start its CPU ad edits.

Scheduled agents must inspect current product facts and save the required video job. They cannot complete the cycle by writing an unrelated draft, switching tools or inventing a publication. The source clip is frozen to its production cycle and must be included in the ad. Local H3 stays under its incident hold; these changes do not clear it or run any GPU model. Blender guides use the existing four-thread CPU Cycles configuration.
